# MEYERTEC Print

Настольное приложение для подготовки маркировки и печати на GoDEX G530. Проекты `.mprj` и шаблоны `.mtemplate` можно переносить между Windows и Linux.

## Установка

Для Windows x64 предусмотрен MSI, для Linux amd64 на базе Debian — пакет DEB. Оба содержат среду выполнения .NET. Команды сборки и установки приведены в [инструкции к пакетам](packaging/README.md).

## Проекты, шаблоны и печать

1. Создайте проект с нуля или из библиотеки шаблонов. Встроенные шаблоны включают рулонную этикетку 60 × 30 мм, полиэстер 40 × 20 мм, сплошную ленту 60 × 15 мм и клеммную маркировку 50 × 6 мм. Перед печатью сверьте ширину, шаг подачи и поля с материалом и принтером.
2. Добавьте текст, QR-коды, штрихкоды или изображения. Свойства объекта задают положение, размеры, параметры шрифта, автоподгонку текста и инверсию цвета.
3. Для переменных данных импортируйте CSV/Excel и сопоставьте столбцы с полями макета. Excel поддерживает `.xlsx`, `.xls` и `.xlsb`, включая выбор листа. CSV поддерживает `;`, `,`, табуляцию, многострочные поля в кавычках, UTF-8, UTF-16 и Windows-1251. Автоматический режим сначала пробует UTF-8, затем Windows-1251.
4. Автонумерация заполняет выбранное поле последовательностью с началом, шагом, ведущими нулями, префиксом и суффиксом. Первая запись задаёт значения макета. Остальные записи можно добавлять, редактировать, дублировать и удалять. Представление ленты показывает порядок этикеток и расчётную длину одного комплекта с межэтикеточными зазорами.
5. Проверьте макет и диапазон записей в предпросмотре. В настройках выберите принтер и подключение, задайте носитель, тираж и параметры печати. В .mprj хранятся данные проекта и настройки выбранного подключения.

Флажок «Применить к остальному» на ленте включает общий макет первой этикетки. При снятом флажке любую этикетку можно открыть в редакторе и настроить отдельно. Индивидуальные макеты сохраняются в `.mprj` и используются при возврате в этот режим. Команда «Файл → Экспорт CSV / Excel…» записывает данные каждой этикетки отдельной строкой в `.csv` или `.xlsx`.

В шаблоне «Terminal marker · 50 × 6 mm» ширина поперёк головки составляет 50 мм, шаг подачи составляет 6 мм. Вырез на левом крае повторяется через каждые две секции. Надпись центрируется по высоте секции и по ширине рабочей области справа от выреза. Исходная длина выреза вдоль подачи составляет 3 мм. Измеренное значение можно задать в поле «Длина выреза, мм» в настройках носителя, а в Windows также в окне печати. Форму, шаг и длину выреза сохраняют `.mprj` и `.mtemplate`.

Для ручного старта совместите передний край первой секции с линией печати. В поле «Первая секция у головки» укажите её форму. При печати через системную очередь выберите в драйвере сплошной носитель.

Шаблон 50 × 6 мм включает «Выравнивать по боковому вырезу» для GoDEX SDK или прямого EZPL по USB или Ethernet. Проверьте, что вырез проходит через датчик и в режиме с зазором FEED стабильно подаёт ленту на 12 мм между вырезами. При выравнивании принтер протягивает один пустой цикл, затем приложение отсчитывает начало первой целой секции от конца выреза. При вырезе длиной 3 мм этот отступ составляет 1,5 мм. Для ручного старта снимите флажок выравнивания.

Одинаковое смещение всех отпечатков корректируется в миллиметрах в окне печати. X управляет положением поперёк ленты. Положительный Y отодвигает изображение от переднего края секции. При нарастающем смещении уточните шаг. Измерьте расстояние между вырезами через несколько секций и разделите его на число секций на этом отрезке.

## GoDEX G530

В Windows можно печатать через установленную очередь или через GoDEX EZio SDK. Сборка Windows x64 из этого репозитория копирует `EZio64.dll` рядом с приложением. Для USB установите драйвер GoDEX. В режиме «GoDEX SDK (EZio)» можно выбрать USB-очередь GoDEX G530 и оставить поле USB ID пустым. SDK передаёт команды EZPL через эту очередь. [Документация GoDEX EZio](https://github.com/godexsw/EZPL_DLL/tree/4c4f76df8d2f7d67e81c1c76bc8f40d51a0e904c)

SDK поддерживает USB (выбранная очередь или идентификатор устройства EZio), RS-232 (COM1–COM4) и Ethernet (TCP 9100). Прямой режим EZPL доступен для Ethernet и RS-232, а в Linux также для USB через распознанный интерфейс `usblp` с правами записи на соответствующее устройство. Системная очередь Windows использует настройки драйвера.

Режимы SDK и прямого EZPL применяют нагрев в единицах плотности GoDEX от 0 до 19 и отступ остановки материала целыми миллиметрами от 0 до 40. Фактическая работа резака зависит от установленного узла и настроек принтера. Для производственной печати проверьте первый отпечаток, подачу материала и читаемость кодов на G530.

## Библиотека и FTP

В библиотеке кнопка «Редактировать…» меняет название, материал и длину выреза и сохраняет новую версию шаблона. Для изменения текста, объектов и размеров макета создайте проект из шаблона, отредактируйте его и сохраните как новую версию через «Шаблоны → Сохранить шаблон». В библиотеке также можно импортировать или экспортировать `.mtemplate` и заменить иллюстрацию своим PNG. Шаблон хранится как читаемый JSON. При редактировании вне приложения сохраните идентификатор и увеличьте `version`. Адреса устройств и учётные данные остаются локальными.

Когда появится сервер, разместите рядом файлы `.mtemplate` и `manifest.json`. В `templates` манифеста укажите для каждого файла следующие поля.

| Поле | Назначение |
| --- | --- |
| `id` | Идентификатор шаблона из файла |
| `name` | Название в списке обновлений |
| `version` | Целочисленная версия шаблона |
| `file` | Имя файла `.mtemplate` в каталоге манифеста |
| `sha256` | SHA-256 опубликованного файла, 64 шестнадцатеричных символа |

Манифест имеет поля `schemaVersion` со значением `1` и `templates` со списком таких записей. Введите адрес вида `ftp://сервер/каталог/manifest.json` в окне обновления. Для явного FTPS включите шифрование и добавьте учётные данные для текущего сеанса при необходимости. Приложение показывает новые шаблоны и более свежие версии, проверяет SHA-256 и устанавливает выбранное обновление по команде пользователя. Установленные версии можно использовать без сети.

## Сборка и тесты

Нужен .NET SDK 10. Запускайте из корня репозитория. Пути артефактов вынесены отдельно, поскольку в истории репозитория есть файлы сборки.

```bash
export DefaultItemExcludes='bin/**;obj/**'
dotnet build MeyertecPrint.csproj -c Release -p:EnableWindowsTargeting=true --artifacts-path /tmp/meyertec-windows
dotnet build Linux/MeyertecPrint.Linux.csproj -c Release --artifacts-path /tmp/meyertec-linux
dotnet run --project tests/CoreTests/CoreTests.csproj --artifacts-path /tmp/meyertec-tests
```

Для запуска Windows-самопроверки передайте `--selftest` приложению из той же сборки Windows. Матрица соответствия приведена в [чек-листе AD1002](AD1002-CHECKLIST.md).

## Автосохранение и WSTX

Windows-редактор сохраняет аварийные копии в `%LOCALAPPDATA%\MeyertecPrint\Recovery`. Для переноса используйте .mprj. Обмен WSTX в Windows сохраняет некоторые свойства в расширении MEYERTEC. Взаимная совместимость с приложениями WAGO требует проверки.
